# Kit trial, 2026-11-25

Phase 5 of the build prompt: each kit command run once on a scratch repo, and what
happened. This is not the owner's day, setup or handoff done test; those are theirs to run
on real work.

## Set-up

- **Scratch repo:** `scripts/kit-trial.mjs` builds a tiny Node package (`src/add.js`, one
  `node --test` test, a lint script, a README) with a local bare origin, in this repo's
  gitignored `.scratch/kit-trial/`. Nothing was written outside this repo, and nothing was
  pushed anywhere but that local origin.
- **Sessions:** each command ran in a fresh `claude -p` session (Claude Code 2.1.302) in
  the scratch repo, with `--permission-mode acceptEdits` and only `Bash(git:*)`,
  `Bash(npm:*)` and `Bash(node:*)` allowed. A headless session can't ask for anything
  else, so every other request was refused, which is how two of the findings below
  surfaced. Prompts that could need an answer said nobody was there to give one.
- **Caveat:** the scratch repo is inside this repo. Claude Code loads `CLAUDE.md` from
  parent folders, so every session also saw this repo's `CLAUDE.md`, which holds the same
  kit rules. Two sessions mentioned it.

## What this found

Each is parked as a `[tool]` line in `BACKLOG.md`, not fixed:

1. **`/setup` can't install the commands without a person.** Writing into `.claude/` needs
   approval, and headless mode can't give it. In an interactive session it asks, so
   this blocks only the night runner or a scripted setup.
2. **`/setup` needs a read outside the repo for its templates.** It found them only after
   reads of `~/.claude/skills/setup/` were allowed. In an interactive session it would
   ask. Naming the folder as `${CLAUDE_SKILL_DIR}/templates/` (parked in T-0003) would make
   it unambiguous.
3. **`/setup` branches and doesn't commit, and the skill says neither.** Both runs made a
   branch (`kit-setup`, `chore/kit-setup`) and left everything uncommitted. That's safe,
   but the skill doesn't say what to do.
4. **`/setup`'s `DESIGN.md` rule reads two ways.** Run 1 wrote a no-UI `DESIGN.md`; run 2
   skipped it. The skill says "if there is UI".
5. **`/done` and `CLAUDE.md` disagree on a draft card.** The skill says to set `blocked`
   when anything fails; the `CLAUDE.md` section says to stop on a draft. The session kept
   `draft` and wrote no evidence. The skill could say what to do on a card that isn't
   `in progress`.
6. **`/park` doesn't say whether to commit.** It left the line uncommitted; `/handoff`
   committed it later. On a machine that doesn't hand off, a parked line could sit
   uncommitted.

- A second machine: `/handoff` pushed to a local path, and no other machine fetched it.
